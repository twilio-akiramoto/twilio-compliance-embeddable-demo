QUICK REFERENCE GUIDE
─────────────────────────────────────────────────────────

START THE DEMO
──────────────
  Command:    ./start.sh
  
  What it does:
  • Checks for existing processes
  • Installs dependencies (if needed)
  • Starts backend on port 3011
  • Starts frontend on port 3010
  • Validates health endpoints
  • Opens browser (macOS)
  • Creates PID files
  
  Expected output:
    ✅ Backend started (PID: xxxxx)
    ✅ Frontend started (PID: xxxxx)
    🎉 Demo Started Successfully!
  
  URLs:
    Frontend:  http://localhost:3010
    Backend:   http://localhost:3011
  
─────────────────────────────────────────────────────────

STOP THE DEMO
─────────────
  Command:    ./stop.sh
  
  What it does:
  • Gracefully stops backend
  • Gracefully stops frontend
  • Force kills if needed
  • Cleans up PID files
  • Frees ports 3010 and 3011
  
  Expected output:
    ✅ Backend stopped
    ✅ Frontend stopped
    ✅ Demo Stopped Successfully!

─────────────────────────────────────────────────────────

CHECK STATUS
────────────
  Command:    ./status.sh
  
  What it shows:
  • Running/stopped status
  • Process IDs (PIDs)
  • Health check results
  • CPU and memory usage
  • Mock mode status
  • Port occupancy
  
  Exit codes:
    0 = All services running
    1 = Some services running
    2 = No services running
  
─────────────────────────────────────────────────────────

RESTART
───────
  Command:    ./restart.sh
  
  What it does:
  • Stops all servers
  • Waits 2 seconds
  • Starts all servers
  
  Same as:    ./stop.sh && ./start.sh

─────────────────────────────────────────────────────────

VIEW LOGS
─────────
  Backend logs:
    tail -f logs/backend.log
  
  Frontend logs:
    tail -f logs/frontend.log
  
  Both logs:
    tail -f logs/*.log

─────────────────────────────────────────────────────────

TROUBLESHOOTING
───────────────

Problem: Port already in use
Solution: ./stop.sh

Problem: Servers won't start
Solution: Check logs/backend.log and logs/frontend.log

Problem: Network error in browser
Solution: Verify backend is running with ./status.sh

Problem: Stale PID files
Solution: rm -f logs/*.pid && ./start.sh

─────────────────────────────────────────────────────────

WORKFLOW EXAMPLES
─────────────────

First time setup:
  1. Edit backend/.env (add credentials)
  2. ./start.sh
  3. Open http://localhost:3010

Daily usage:
  ./start.sh      # Morning: start work
  ./status.sh     # Check if running
  ./stop.sh       # Evening: end work

After changing config:
  ./restart.sh

Before deploying:
  ./stop.sh       # Clean slate
  ./start.sh      # Fresh start
  ./status.sh     # Verify

────────────────

  lsof -ti:3011 | xargs kill -9

Check running processes:

──────────
